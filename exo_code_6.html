Une école d’ingénieurs souhaite automatiser la gestion des stages effectués par ses étudiants en entreprise.

Dans ce cadre, le service des stages envisage de développer une application orientée objet, basée sur les règles de gestion décrites dans le cahier des charges ci-dessous.

Chaque étudiant est défini par les informations suivantes : nom, prénom, numéro de téléphone et numéro d’étudiant.

Il est demandé de créer une classe Etudiant qui modélise ces caractéristiques selon les règles suivantes :

  • Les attributs doivent être nommés comme suit :
    • nom : pour le nom ;
    • prenom : pour le prénom ;
    • tel : pour le numéro de téléphone ;
    • numEtud : pour le numéro d’étudiant.
  • Toutes ces caractéristiques sont de type chaîne de caractères.
  • L’ordre de présentation des attributs dans le constructeur doit respecter l’ordre indiqué dans le cahier des charges.
  • Toutes les caractéristiques sont accessibles pour la lecture.
  • Seules les caractéristiques tel et numEtud peuvent être modifiées après la création de l’objet.
  • La création d’un étudiant peut se faire de deux manières :
    1. En fournissant toutes les caractéristiques (nom, prénom, téléphone et numéro d’étudiant) ;
    2. Ou en fournissant uniquement le nom, le prénom et le numéro d’étudiant.
  • La classe Etudiant doit permettre de comparer deux étudiants en fonction de leur numéro d’étudiant grâce à une méthode nommée Equals qui retourne un booléen.
